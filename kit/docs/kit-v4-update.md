# هماهنگ‌سازی کیت تازه و موزیک‌پرامپت — آرشیو محلی v4

## منبع و محدوده

GitHub main به upload `0362650` به‌روز شده بود. شاخهٔ همین جلسه `arena/ece99e55-instareel` پس از fetch history، بدون تعویض شاخه با آن fast-forward شد. دو فایل تازه در ریشه بودند: `nail-reel-kit.zip` (43,698 bytes) و `music-prompts.md`. «v4» صرفاً نام محلی آرشیو ماست؛ فایل ZIP شمارهٔ نسخه ندارد.

ZIP با کنترل مسیر مطلق/traversal، symlink، حجم و CRC هنگام خواندن استخراج شد. **۱۸ فایل منبع** دقیقاً در `reference/kit-v4/kit/` نگه‌داری شد؛ SHA256 ZIP و تک‌فایل‌ها در `manifest.json` است. دو فایل `__pycache__/*.pyc` فایل تولیدی‌اند: اجرا/وارد پروژه نشدند؛ مسیر و hash آن‌ها در manifest ثبت است. ZIP پس از اعتبارسنجی حذف شد؛ منبع در upload commit محفوظ است. آرشیوهای v2 و v3 تغییر نکردند.

## چه چیز واقعاً تازه است؟

- README دارای **Motion budget** تازه است: تغییر بصری سریع‌تر، دامنهٔ حرکت دوربین بیشتر، زاویه/محیط تازه، کلوزآپ و نمای باز، secondary motion، اغراق احساس و reaction hold کوتاه. این بخش وارد راهنمای فعال شد تا سناریوی بعد بر همین اساس طراحی شود، نه صرفاً تعویض متن روی نماهای ۰۸.
- ابزار `render/motion_check.py` اضافه شده: نسخهٔ اصلی عیناً در archive است. نسخهٔ اجرایی با مسیر مستقل ورودی/خروجی، FFmpeg محلی یا imageio-ffmpeg، گزارش JSON، خطای ویدئوی کوتاه، `--strict` و استثنای صریح کارت به مسیر production اضافه شد.
- موزیک‌پرامپت سناریوی **۱۰ / ink doodle** اضافه است: **96 BPM**، acoustic/lo-fi با مسیر **playful → tender → uplifting**، ukulele/whistle، سپس felt piano/pads و پایان امیدوارکننده. فایل ریشه با فایل داخل ZIP بایت‌به‌بایت یکسان است. `kit/music-prompts.md` با آن هماهنگ شد، همراه یادداشت مسیر ترک محلی و مجوز.
- voice-prompts شامل سناریوی ۱۰ «۴ نوع دوست که با مشتری میان» و delivery نرم‌تر در turn/friend/payoff است. این **مرجع احتمالی** است، نه سناریوی ارسالی کاربر و نه مجوز فعال‌کردن گوینده. فایل پرامپت فعال به‌روز شد؛ تنظیم voice=false باقی است.
- اسکلت ZIP پشتیبانی per-scene `hold` به audio/index افزوده؛ در آرشیو ثبت و برای تدوین بعد در دسترس است. **این قابلیت در تمام rendererهای تولید فعلی پیاده‌سازی یا تست نشده**؛ برای سناریوی بعد باید duration/hold و timing همان renderer صریح طراحی و تست شود. فعلاً engine/audio فعال دست‌نخورده‌اند.

## تقدم‌ها و مرز ادعا

سناریوی تازه هنوز دریافت نشده است. نمونهٔ ۰۱ در ZIP و خطوط نمونهٔ ۱۰ جایگزین سناریوی فعال نمی‌شوند. هنگام رسیدن سناریو، `style` آن بر راهنمای عمومی blob/cartoon مقدم است؛ داستان، نوع موسیقی، BPM و beatها طبق آن انتخاب می‌شوند. درخواست قبلیِ بدون گوینده، نبود عنوان اضافه و حفظ خروجی‌های قبل برقرار است.

ادعاهای متن خام کیت دربارهٔ ترتیب قطعی وزن الگوریتم، تعیین توزیع توسط سه ثانیهٔ اول، یا تغییر هر دو ثانیه **یافتهٔ اثبات‌شدهٔ عمومی نیستند**. در README فعال به‌عنوان هدف خلاقهٔ پروژه، نه قانون اکسپلور، صورت‌بندی شدند؛ اصل متن آرشیو تغییر نکرد. هدف حرکت زیاد نباید با نویز، لرزش بی‌دلیل یا ناخوانایی کارت برآورده شود. پژوهش قبلی `docs/research/reel-attention-research.md` و تفکیک شواهد همچنان معتبر است.

شاخص اختلاف پیکسل حرکت کاراکتر را از تغییر نوشته/نویز/کات تشخیص نمی‌دهد. `jumpSamples` یعنی نمونه‌های پرجهش، نه شمار قطعی کات‌ها. mean>=3 و static<1s معیار داخلی این کیت هستند، نه پیش‌بینی retention یا رسیدن به Explore. برای خروجی تازه علاوه بر این ابزار، ارزیابی بصری و تست زیرنویس/صدا/ساختار لازم است.

## استفاده در سناریوی بعد

```sh
# پس از طراحی طبق سناریوی تازه و رندر:
.venv/bin/python kit/render/motion_check.py path/to/new-reel.mp4 --strict
# فقط بازهٔ واقعیِ کارت ثابت را با زمان سراسری ویدئو مستند و معاف کن:
.venv/bin/python kit/render/motion_check.py path/to/new-reel.mp4 --strict --allow-static 20:23
```

عددهای مثال بالا زمان سناریوی بعد نیستند. مسیر گزارش پیش‌فرض `kit/out/<video-stem>-motion.json` است. `--strict` شکست اهداف را با exit 1 گزارش می‌کند؛ بدون آن ابزار فقط diagnostic است. source music از `audio/music.mp3` سپس wav/m4a با importer موجود تأمین می‌شود؛ API آهنگ‌سازی فراخوانی نشده، فایل موسیقی آماده‌ای در ZIP نیست و هیچ آهنگ تازه‌ای تولید نشده است.

## بررسی‌ها

- تمام ۱۸ فایل منبع archive از روی manifest تطبیق داده شدند؛ دو نسخهٔ root/ZIP موزیک‌پرامپت یکسان‌اند.
- هر هشت MP4 موجود و brand، سناریوی فعال، post copy، engine، audio dispatcher، render و lockfile با upload commit یکسان‌اند؛ hashها در `evidence-kit-v4/integration-qa.json` ثبت است.
- ۹ تست importer موزیک پاس شدند.
- تست‌های واحد حرکت: ویدئوی ثابت رد می‌شود؛ استثنای مستند static را حذف می‌کند؛ حرکت کافی پاس می‌شود؛ ورودی خیلی کوتاه رد می‌شود.
- ابزار روی **نسخهٔ قبلی ۰۸-recut** اجرا شد: mean motion حدود **1.54** است و هدف تازهٔ >=3 را پاس نمی‌کند. نتیجه صادقانه به‌عنوان baseline ذخیره شد؛ ادعای پاس‌شدنِ استاندارد تازه برای ریل قبلی نداریم. فایل قبلی عمداً بازسازی/بازنویسی نشد، چون درخواست این مرحله فقط آمادگی برای سناریوی جدید است.

آمادهٔ دریافت پرامپت سناریوی بعد هستیم؛ تولید انیمیشن جدید هنوز آغاز نشده است.
